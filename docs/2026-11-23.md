## 2교시 · IP 주소 · 사설과 공인

### 문제 2-1 · 내 IP 를 2진수로
- (가) 192 11000000 / 168 10101000 / 100 01100100 / 74 01001010
- (나) format(number, "08b")는 마디 하나의 숫자를 8자리 2진수 글자로 바꿔줍니다. `08`을 쓰는 이유는 마디마다 자릿수를 8자리로 고정해야 주소의 구조를 일정하게 보고 비교하기 편하기 때문입니다.
- (다-1) IPv4 주소는 4개의 마디로 되어 있고, 마디 하나는 8비트입니다. 8비트로 나타낼 수 있는 가장 작은 수는 0, 가장 큰 수는 255입니다.
- (다-2) 32비트로 만들 수 있는 주소는 모두 2의 32제곱(2^32) 개입니다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소
- (가) ipconfig: 192.168.100.74 / curl: 1.245.252.171
- (나-1) ipconfig 주소(192.168.100.74)는 사설 IP(192.168.0.0 ~ 192.168.255.255 범위)이고, curl 주소(1.245.252.171)는 세 가지 사설 범위에 속하지 않으므로 공인 IP입니다.
- (나-2) 172.17.9.3은 둘째 마디가 17(16~31 범위)이므로 내부망 장비로 분류하고, 172.33.9.3은 둘째 마디가 33(범위 밖)이므로 외부 주소로 분류해야 합니다.
- (다-1) NAT가 내부망 PC의 사설 IP를 공유기의 공인 IP로 변환하여 내보내기 때문입니다. 같은 공인 IP를 여러 PC가 함께 사용하므로, 특정 PC를 찾으려면 NAT 변환 기록(포트 번호 매핑)을 함께 봐야 합니다.
- (다-2) 정적 NAT은 사설 IP와 공인 IP를 1:1로 고정 매핑하고, 동적 NAT은 여러 사설 IP를 공인 IP 풀에 유동적으로 매핑합니다. 인터넷에 공개하는 회사 웹 서버는 외부 사용자가 늘 같은 주소로 찾아와야 하므로 정적 NAT이 맞습니다.

### 이 교시에 새로 안 것
- IP 주소가 32비트라는 것과, 사설 IP와 공인 IP의 차이 및 NAT의 역할을 알게 되었습니다.

## 3교시 · 서브넷 마스크 · CIDR

### 문제 3-1 · 내 서브넷 마스크 읽기
- (가) 서브넷 마스크: 255.255.0.0, CIDR: /16, 주소 수: 65,536, 사용 가능한 호스트 수: 65,534 / 내 주소의 네트워크 부분: 192.168, 호스트 부분: 100.74
- (나-1) 서브넷 마스크의 1은 네트워크 부분, 0은 호스트 부분을 가리킵니다. 내 마스크(255.255.0.0)는 1이 16개이므로 CIDR은 /16입니다.
- (나-2) 같은 교실의 다른 PC와 주소를 비교하면 네트워크 부분(192.168)은 같고, 호스트 부분(100.74)은 다릅니다. 같은 망에 있기 때문입니다.
- (다-1) 내 마스크(/16) 기준으로 10.1.3.8과 10.1.7.8은 앞 두 마디(10.1)가 같으므로 같은 망입니다. /24 기준으로 보면 셋째 마디(3과 7)가 다르므로 다른 망입니다.
- (다-2) 마스크에 따라 같은 망인지 판정이 달라지므로, 같은 망이면 스위치로 바로 보내고 다른 망이면 게이트웨이를 거치게 됩니다. 방화벽 규칙도 망 단위로 설정하므로 판정이 틀리면 통신이 차단되거나 허용되는 오류가 발생합니다.

### 문제 3-2 · 내 망 범위
- (가) 192.168.100.74/16 → 255.255.0.0 / 192.168.0.0 / 192.168.255.255
- (나-1) 첫째 줄은 서브넷 마스크, 둘째 줄은 네트워크 주소, 셋째 줄은 브로드캐스트 주소입니다. 내 주소에서 0과 255로 바뀐 마디는 뒤 두 마디(100.74 → 0.0, 255.255)입니다.
- (나-2) 내 주소와 마스크를 AND 연산하면 네트워크 주소가 나옵니다. 마스크가 0인 호스트 부분(뒤 두 마디)만 0으로 바뀌고, 마스크가 1인 네트워크 부분(앞 두 마디)은 그대로 유지됩니다.
- (다-1) 예, 기본 게이트웨이 주소(192.168.1.1)는 192.168.0.0과 192.168.255.255 사이에 있습니다.
- (다-2) 게이트웨이는 같은 망 안의 장비여야 통신이 가능합니다. 네트워크 주소나 브로드캐스트 주소는 망 전체를 가리키는 주소이므로 장비에 설정할 수 없습니다.

### 이 교시에 새로 안 것
- 서브넷 마스크와 CIDR의 의미, 그리고 ipaddress 모듈로 네트워크 주소와 브로드캐스트 주소를 계산하는 방법을 알게 되었습니다.

## 4교시 · 서브네팅

### 문제 4-1 · 반으로 나누기 /25
- (가) 192.168.50.0/25 / 192.168.50.128/25
- (나-1) 192.168.50.128/25에서 / 앞의 주소는 그 블록의 네트워크 주소입니다. /25 블록 하나의 주소 수는 128개이므로 0~127, 128~255로 나뉘어 .128에서 나뉩니다.
- (나-2) 126개씩 자르지 않고 128개씩 자르는 이유는 블록의 크기가 2의 거듭제곱(128)이어야 서브넷 마스크를 깔끔하게 적용할 수 있기 때문입니다. 사용 가능한 호스트 수는 주소 수(128)에서 네트워크 주소와 브로드캐스트 주소 2개를 뺀 126개입니다.
- (다-1) /26의 주소 수는 64개, 사용 가능한 호스트 수는 62개입니다. 2개 차이는 네트워크 주소와 브로드캐스트 주소 때문입니다.
- (다-2) /26 블록의 사용 가능한 호스트 수는 62개인데 부서 장비가 64대이므로, 주소가 2개 부족하여 장비를 모두 수용할 수 없습니다.

### 문제 4-2 · 겹침 검사
- (가) 첫 파일: False, 두 번째 파일: True
- (나-1) 운영팀 망을 192.168.50.64/26으로 바꾸자 True가 나왔습니다. 개발팀 망(192.168.50.0/25, 범위 .0~.127)과 운영팀 망(192.168.50.64/26, 범위 .64~.127)이 .64~.127 구간에서 겹치기 때문입니다.
- (나-2) 겹치는 주소 구간은 192.168.50.64 ~ 192.168.50.127입니다.
- (다) 두 장비가 같은 IP 주소를 받으면 통신 충돌이 발생하여 통신이 끊기거나 엉뚱한 장비로 데이터가 전달됩니다. 관제 로그를 읽을 때도 같은 IP로 기록되어 어느 장비의 통신인지 구분할 수 없게 됩니다.

### 이 교시에 새로 안 것
- 서브네팅 시 블록 크기(주소 수)와 사용 가능한 호스트 수의 차이, 그리고 두 망이 겹치는지 코드로 검사하는 방법을 알게 되었습니다.
