### 문제 5-2 (TCP/UDP/ICMP 구분)

  ① `TCP`

  ④ `UDP`

### 문제 5-3 (세 번의 순서 맞히기)
- 세 패킷의 순서와 방향: `(나) [SYN] (내 PC → 서버) → (다) [SYN, ACK] (서버 → 내 PC) → (가) [ACK] (내 PC → 서버)`
- 🔍 연결을 맺을 때는 세 번인데, 끝낼 때는 왜 네 번인가요?
  답: `연결을 맺을 때는 서버가 「알았다(ACK)」와 「나도 연결하자(SYN)」를 한 번에 보낼 수 있지만, 끝낼 때는 서버가 아직 보낼 데이터가 남아있을 수 있어 「알았다(ACK)」와 「나도 다 보냈다(FIN)」를 나누어 보내야 하기 때문입니다.`

### 문제 5-4 (두 연결의 차이)

## 최종 분석

### 1. 연결이 열리는 순간 — 3-way handshake
- 세 줄의 Source → Destination 과 Info: 
  - `192.168.100.74 → 104.20.23.154 [SYN]`
  - `104.20.23.154 → 192.168.100.74 [SYN, ACK]`
  - `192.168.100.74 → 104.20.23.154 [ACK]`
- 세 줄이 오간 뒤 두 컴퓨터는 어떤 상태가 되나요?
  답: `서로 연결이 수립된 상태(ESTABLISHED)가 되어 데이터를 주고받을 수 있게 됩니다.`

### 2. 패킷 하나를 열어 본 값 —
- 출발지 · 목적지 IP (3층) · TTL · 출발지 · 목적지 포트 (4층): `192.168.100.74 → 104.20.23.154 · TTL (캡처 화면 확인) · 56921 → 80`
- 목적지 포트를 보고 어떤 서비스로 가는 패킷인지 알 수 있나요? 4.1 표를 근거로 설명합니다.
  답: `네. 80번 포트는 HTTP(암호화되지 않은 웹) 서비스로 가는 패킷임을 알 수 있습니다.`

### 3. HTTP 요청 —
- 요청 줄에서 그대로 보인 내용: `GET /?q=network_day1 HTTP/1.1`
- 이것이 보안에서 문제가 되는 이유는 무엇인가요?
  답: `HTTP는 암호화되지 않아 패킷을 가로채면 요청 내용(URL, 파라미터 등)이 그대로 노출되기 때문입니다.`
