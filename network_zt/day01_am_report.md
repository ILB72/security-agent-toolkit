# Day 1 오전 보고서

## 2교시 · 첫 관찰 — ping

### 문제 2-1 (예시 화면 읽기)
- 보냄 · 받음 · 손실 · 평균: `4 · 3 · 25% · 47ms`
- 손실 % 는 보낸 수와 받은 수로 어떻게 계산했나요?: `(보낸 수 - 받은 수) / 보낸 수 * 100 공식으로 계산합니다. (예: (4-3)/4*100 = 25%)`

### 문제 2-2 (8.8.8.8 ping)
- 8.8.8.8 까지 평균 왕복 시간 · TTL · 받음 · 손실: `평균 35ms · TTL 115 · 받음 10 · 손실 0%`

### 문제 2-3 (google.com ping)
- google.com 의 IP 주소: `142.250.199.206`
- 이름만 입력했는데 IP 주소가 나온 이유는 무엇인가요?: `컴퓨터는 이름(도메인)으로 통신할 수 없기 때문에, DNS 서버를 통해 도메인 이름을 IP 주소로 변환한 뒤 통신하기 때문입니다.`

### 문제 2-4 (두 가지 실패 구별)
- 두 실패 문구: 
  - 첫 번째: `Ping 요청에서 abc.nowhere-not-exist 호스트를 찾을 수 없습니다.`
  - 두 번째: `요청 시간이 만료되었습니다.`
- 두 실패는 각각 어디에서 멈춘 것인가요?: 
  - 첫 번째는 **DNS(도메인 이름 해석) 단계**에서 멈췄습니다. (이름을 IP로 바꾸지 못해 패킷을 보내지도 못함)
  - 두 번째는 **IP 주소(3계층)** 까지 도달했으나, 상대방(또는 경로 상의 장비)이 응답을 주지 않아 실패했습니다.

## 3교시 · OSI 7계층 ① 아래 세 층

### 문제 3-1 (예시 화면 읽기)
- 예시 화면의 IPv4 주소 · MAC 주소 · 기본 게이트웨이: `192.168.0.15 · A4-B1-C2-D3-E4-F5 · 192.168.0.1`

### 문제 3-2 (내 IP · 게이트웨이 · MAC 주소)
- 찾은 장치 이름 · 내 IPv4 주소 · 기본 게이트웨이 · MAC 주소: `이더넷 어댑터 이더넷 3 · 192.168.100.74 · 192.168.1.1 · D8-BB-C1-40-30-A6`

### 문제 3-3 (게이트웨이 ping)
- 게이트웨이까지 평균 · 2-2 의 8.8.8.8 평균: `게이트웨이까지 평균 0ms · 8.8.8.8 평균 35ms`
- 게이트웨이까지가 더 짧은 이유는 무엇인가요?: `게이트웨이는 같은 건물(같은 망) 안에 있는 장비라 물리적 거리가 가깝고, 8.8.8.8은 인터넷 건너편(구글)에 있기 때문입니다.`

### 문제 3-4 (ARP 캐시 보기)
- 게이트웨이 줄의 MAC 주소 · 유형: `00-10-f3-a3-fc-96 · 동적`
- 🔍 ARP 는 무엇을 알아내려고 쓰나요?: `같은 망 안에서 IP 주소만 알고 있는 상대의 MAC 주소를 알아내기 위해 사용합니다. 내 PC가 기본 게이트웨이(192.168.1.1)로 데이터를 보내려면 IP뿐만 아니라 실제 하드웨어 주소인 MAC 주소도 알아야 하는데, 이때 ARP를 사용해 알아내고 '동적'으로 캐시에 저장합니다.`

## 4교시 · OSI 7계층 ② 위 네 층

### 문제 4-1 (warmup.py)
- 출력 두 줄: `HTTPS` / `모름`
- 3389 는 사전에 없는데도 에러 없이 둘째 줄이 나온 이유는 무엇인가요?: `파이썬의 .get() 메서드를 사용했기 때문입니다. 사전에 없는 키를 대괄호([])로 조회하면 KeyError 에러가 발생하지만, .get(키, 기본값)을 사용하면 에러 없이 기본값("모름")을 반환합니다.`

### 문제 4-2 (netstat -ano)
- 고른 줄의 외부 포트 → 서비스 이름 · PID → 프로그램 이름: `192.168.100.74:49394 ↔ 104.18.37.228:443 (ESTABLISHED) / 443 → HTTPS / 5852 → ChatGPT.exe`

### 문제 4-3 (LISTENING 포트)
- 4.1 표에 있는 LISTENING 포트 → 서비스 이름: `135 → RPC, 445 → SMB`
- 🔍 LISTENING 과 ESTABLISHED 는 무엇이 다른가요?: `LISTENING은 내 PC의 프로그램이 연결 요청을 기다리며 포트를 열어둔 상태입니다. (예: 0.0.0.0:445) ESTABLISHED는 상대방과 이미 연결되어 실제 데이터를 주고받고 있는 상태입니다. (예: 192.168.100.74:49394 ↔ 104.18.37.228:443)`

### 문제 4-4 (증상으로 층 좁히기)
- 증상 ① · ② · ③ 에서 의심되는 층: 
  - ①: `7계층 (응용 계층 - DNS)`
  - ②: `3계층 (네트워크 계층 - 게이트웨이/라우팅) 또는 2계층`
  - ③: `4계층 (전송 계층 - 포트) 또는 7계층 (응용 계층)`
- 증상마다 그렇게 판단한 근거는 무엇인가요?: 
  - ①번: `숫자 IP(8.8.8.8)로는 통신이 되므로 3계층까지는 정상입니다. 도메인 이름(google.com)을 IP로 변환하는 DNS(7계층)에서 실패한 것입니다.`
  - ②번: `기본 게이트웨이(공유기)와 통신이 안 되므로, 내 PC가 속한 로컬 망(2~3계층)이나 물리적 연결(1계층)에 문제가 있을 가능성이 큽니다.`
  - ③번: `ping(3계층)은 성공하므로 네트워크 경로는 정상입니다. 특정 웹사이트가 안 열리는 것은 해당 사이트의 웹 서비스(7계층) 문제이거나, 해당 포트(4계층)가 막혀있을 가능성이 있습니다.`
